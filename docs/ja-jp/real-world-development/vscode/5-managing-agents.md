GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat はマシン上でリアルタイムに実行される作業を表示するため、ツールの呼び出しやファイルの編集状況を確認できます。差分をインラインでレビューし、個々の変更を受け入れるか取り消すかを選び、エディターを離れずに追加のプロンプトを送って作業を調整・拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッション中にエージェントへ指示を送り、高コントラストに加えてライトモードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、高コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライトモードの切り替えも追加してほしいと依頼がありました。新しい会話を最初から始めるのではなく、既存のセッションに追加の指示を送って作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集などを確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求められたターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を取り消し、エージェントに別の方法を試させます。
4. チャットの上部にある **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの使用許可を求められた場合、エージェントは一時停止して **Allow** を表示します。問題ないと判断したコマンドのみ承認してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう依頼する

高コントラスト モードができたので、同じ会話でライトモードの切り替えも追加します。同じチャット セッションを続けることで、エージェントは前の作業から得たコンテキスト、変更したコンポーネント、スタイル設定の方法、ローカル ストレージを使った実装パターンを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加に取り組みます。
3. 高コントラスト モードと同様に、新しい編集を1つずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントの方向が希望と異なる場合 (たとえばトグル UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも速く調整できます。追加のプロンプトを使って、変更を依頼します (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方向を修正します (「トグルを3つにせず、ライトモードを既存の設定パネルに統合する」)、範囲を広げます (「両方の切り替えにキーボード ショートカットも追加する」)。

## 作業内容をレビューする

変更をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視し、各ファイル編集を確認して変更を受け入れるか取り消すかを判断し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を受け入れる、または取り消す。
- 追加のプロンプトで進行中のセッションを方向付けする。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
